Shoot on the move

Problem

A ball fired from a moving robot keeps the robot’s velocity. Driving toward or across the line of sight moves where it lands, so a shot table built for a standing robot is not enough. On the turret itself, a plain position PID either lags a moving target or overshoots on large moves.

What I built

I wrote the turret’s aiming cascade and its shot compensation, with contributions from teammates. Both run every 20 ms in the WPILib robot program. The compensation turns the robot’s pose and velocity into a turret angle, a hood angle and a ball exit speed. The controller drives the turret to that angle: an outer loop turns the angle error into a velocity command, and the motor controller’s own velocity loop tracks it.

How it works

The compensation looks ahead to the release moment and splits the velocity into the part toward the target and the part across it. It shortens the aimed distance for motion toward the target, then yaws into the sideways motion: phi = asin(-vPerp / vHoriz). The controller picks SEEK for large errors and TRACK for small ones, with hysteresis and a minimum dwell time. SEEK follows a trapezoid profile with the profile velocity fed forward; TRACK is a P + D term with the target’s rate fed forward. An arrival gate caps the approach speed at sqrt(v_end^2 + 2 a d), the speed a fixed braking rate can still shed before the target. Last, the command subtracts the chassis rotation, so turning the robot does not turn the aim.

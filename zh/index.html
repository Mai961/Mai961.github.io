视觉：AprilTag 定位器 + 场地 EKF

一场录制比赛的回放

在查看器中打开

场地 EKF 将定位器给出的标签定位与相机的视觉惯性里程计（VIO）融合。

EKF 以约 400 Hz 的频率基于 VIO 里程计做预测，并用每次标签定位进行校正。每次定位按定位器计算出的协方差加权。

我先用 Python 编写了 EKF，随后将其移植到 C++ 以降低 CPU 负载。

详情：state-estimation、perception-sqpnp

分析：python state-estimation/replay/analyze_field_ekf.py → 20 s 内 130 次标签更新，频率 400 Hz；记录的新息中位数 1.0 cm。后验残差中位数 0.3 cm，130 次中有 7 次超出 95 % 线（这不是一致性检验：残差会被拉向该次定位）。

分析：python perception-sqpnp/replay/analyze_localizer.py → 183 帧，110 次合并多标签求解；所选标签的重投影误差中位数 0.035 px（日志记录值）；由记录的协方差得到的 σx 中位数 7.5 mm。

场地上的点云

在查看器中打开

AprilTag 定位器将一帧相机图像转换为相机在场地上的位姿，并给出 6x6 协方差。

如果几何构型不可观，就不输出位姿，而不是编造一个协方差。

点云是相机驱动自身的输出；定位器以一位队友的移植版本为起点，其中的合并多标签求解和协方差由我完成。

详情：perception-sqpnp

查看器按钮会在 Lichtblick（Foxglove Studio 的开源构建版本）中连同面板布局打开片段；无需登录。

行进间射击

一个在机器人行驶时持续瞄准的转塔，并针对机器人速度做射击补偿。

从运动中的机器人射出的球会保留机器人的速度。补偿会向前预测，并把速度分解为朝向目标的分量和横穿目标方向的分量。

转塔的瞄准级联控制及其射击补偿由我编写，队友也有贡献。

详情：control/turret-2026

分析：python control/turret-2026/replay/analyze_turret.py → 以最高 3.5 m/s 行驶 30 s，其中补偿开启 17 s：−2.0 至 +1.9 m/s 的横向速度产生了 −40° 至 +34° 的补偿角；补偿期间跟踪误差 RMS 5.2°。

全身控制

机械臂全身控制

在查看器中打开

在查看器中回放

协处理器上的求解器决定整台机器人如何运动。

一个阶段状态机运行 DRIVE、APPROACH、TASK 和 RETRACT 四个阶段。进入 TASK 时，目标被转换到求解器的坐标系中并冻结，因此它保持在场地上的同一点。

目标冻结以及由 QP 控制底盘运动都仅在仿真中实现。

详情：control/wholebody-2026

基于 AprilTag 定位到达场地固定目标

AprilTag 定位告诉机器人自己所处的位置，因此机械臂的目标可以固定在场地上。

机械臂的目标是固定在场地上的位姿，而全身求解器在机器人自身的坐标系中工作。进入 TASK 之前，APPROACH 要求场地位姿是最新的。

展示仓库中没有收录这一演示模式的代码摘录。

详情：control/wholebody-2026、perception-sqpnp、state-estimation

控制栈与基础设施

同一控制器，仿真或实机

在查看器中打开仿真

IO 层是一个带两个后端的接口：通过 CAN 连接的 TalonFX 电机控制器，以及一个运动学的 WPILib 仿真。

全身控制器和阶段状态机无需改动即可对接仿真机器人，经由回环接口上的同一个 UDP 桥通信。替换的是后端，而不是控制器。

仿真中的起点平移了 1 m，因为当前的目标集合移动了这个目标；仿真的被控对象是运动学模型。

详情：sim-io-layer

分析：python sim-io-layer/replay/analyze_sim_vs_real.py → 在 TASK 阶段，测量的关节值与实机周期的 RMS 偏差为 0.056 rad（肩关节）、0.017 m（伸缩臂）和 0.041 rad（腕关节）；从锁定到行驶：仿真 2.36 s，实机 2.38 s。

协处理器 ↔ 控制器桥接

在查看器中打开

Linux 协处理器与机器人控制器之间采用传输时带类型哈希的类型化消息、固定长度的位姿消息和 NTP 式时钟同步，因此位姿和指令的传递在控制器一侧无需中间件。

该日志只包含时钟话题，因此无法给出各话题的消息频率。

详情：udp-bridge

分析：python udp-bridge/replay/analyze_clock.py → 154 s 内 154 个时钟样本中 154 个有效；往返时间中位数 0.34 ms；153 s 内偏移漂移 18 ms。

底盘控制

在 swerve 模块上采用带前馈的级联速度环和航向环：这是转塔和全身控制器所依托的底座，通过同一个 IO 层驱动。

这次运行没有视频。

详情：control/chassis

分析：python control/chassis/replay/analyze_chassis.py → 6.2 s 的自主路径跟随：位置误差 RMS 0.23 m（最大 0.48 m），航向误差 RMS 7.3°，速度最高 3.9 m/s。

自动调参

一个针对机械臂关节的 PID 调参台架，由编程智能体在硬性限制内引导。

智能体决定下一步扫描哪个增益、扫描范围以及何时停止。确定性的扫描本身保留在强制执行这些限制的代码中。

我编写了运行实验的 ROS 2 节点，以及编程智能体所遵循的流程。

详情：llm-tuning-agent

分析：python llm-tuning-agent/replay/analyze_tuning.py → 一次台架测试共 32 次实验（其中 17 次为搜索），无中止：调节时间 1.04 s → 0.76 s，稳态误差 0.109 → 0.007 rad；超调从 0.012 上升到 0.019 rad。
